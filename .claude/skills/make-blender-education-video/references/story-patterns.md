# Story Patterns

Choose one primary pattern. Add at most two supporting patterns so the film retains a clear mental model.

## How it is built

Use for buildings, machines, infrastructure, products, organisms developing over time, and manufacturing.

Sequence: final result → prerequisites → ordered stages → hidden layers → completed system. Show each new stage attaching to an established spatial reference. Use time compression deliberately.

## How it works

Use for engines, devices, biological mechanisms, software-hardware systems, and energy conversion.

Sequence: input → transformation → output → control → failure or constraint. Animate cause before effect. Use repeated cycles only after explaining one complete cycle slowly.

## Inside the system

Use for anatomy, architecture, geology, machines, electronics, and infrastructure.

Sequence: exterior context → section cut → subsystem isolation → relationship between subsystems → reconstructed whole. Preserve camera orientation across scale changes.

## Invisible flows

Use for electricity, heat, air, water, forces, stress, information, chemistry, and biological transport.

Define the visual grammar before using it. Assign consistent meanings to color, direction, speed, density, thickness, and particle behavior. Do not let decorative particles imply quantitative accuracy.

## Scale journey

Use for cells, materials, planets, semiconductor structures, ecosystems, and nested systems.

Anchor every scale transition with a known object, a dimension stated in narration/subtitles, or a retained geometric landmark. Optional dimension labels may be used only when the user explicitly requests them. Avoid an endless zoom that destroys orientation.

## Cause and effect

Use for failures, natural phenomena, engineering tradeoffs, medical mechanisms, and historical processes.

Sequence: initial conditions → trigger → propagation → visible outcome → intervention or alternative. Distinguish correlation from mechanism.

## Comparison or evolution

Use for old versus new technology, species, design alternatives, construction systems, or competing mechanisms.

Keep camera, scale, lighting, and metrics consistent. Change one variable at a time. Use side-by-side views only when both remain legible.

## Shot design template

For each shot, record:

- learning objective;
- claim status;
- starting orientation and scale;
- start state of the subject or process;
- physical, biological, chemical, informational, or conceptual motion driver;
- intermediate state that proves the process is occurring;
- visibly different end state;
- one dominant subject-space visual action, excluding camera movement;
- supporting camera action, if any;
- narration cue;
- optional scene-text request, defaulting to none;
- literal versus conceptual motion;
- exit state that prepares the next shot.

Use a clean overview at the beginning and reassemble the system at the end. A viewer should be able to retell the explanation without remembering every label.
