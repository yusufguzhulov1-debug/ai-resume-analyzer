# Storytelling Guide

Use this guide to turn product research into a clear demo video narrative.

## Core Narrative Shape

A strong product demo video usually follows this order:

1. **Hook**: Name the user's real problem or desired outcome.
2. **Context**: Show the product surface where the work begins.
3. **Action**: Show the user doing the primary action.
4. **Transformation**: Show what changes because the product works.
5. **Review or proof**: Show the result, signal, dashboard, comparison, or external evidence.
6. **Expansion**: Show adjacent features only after the core loop is clear.
7. **CTA**: End with product name, URL, and a concrete next step.

For a 60-90 second video, keep the core loop in the first 35-45 seconds. Secondary features should support the loop, not compete with it.

## Scene Timing

Use this as a starting point:

- 0-6s: Hook and product promise
- 6-18s: Product surface and setup
- 18-34s: Primary action
- 34-48s: Result or transformation
- 48-62s: Proof, review, or comparison
- 62-78s: Feature suite or workflow breadth
- 78-90s: CTA

Shorter social variants can compress to:

- 0-3s hook
- 3-15s workflow
- 15-25s result
- 25-35s proof
- 35-45s CTA

## Copy Rules

- Write for the target user, not for an abstract buyer.
- Use short lines. Moving video text should be understood in one glance.
- Prefer active, concrete copy: "Paste the draft. Review the changes. Submit with confidence."
- Avoid inflated AI language: "revolutionary", "unlock", "seamless", "next-gen", "supercharge", unless the brand already uses it and it fits.
- Do not put paragraphs on screen. Use voiceover or subtitles if the content needs more detail.

## Product Manager Lens

Decide what the user needs to believe after watching:

- I understand what this product does.
- I can imagine myself using it.
- I saw the actual interface.
- I saw the before/after or proof.
- I know what to do next.

Every scene should serve one of those beliefs.

```json
]
```

## Common Story Mistakes

- Showing too many pages before the viewer understands the core loop.
- Opening with company boilerplate instead of user relevance.
- Treating each scene like a separate slide instead of one continuous journey.
- Showing proof before showing what was done.
- Making the product look fake by using generic mockups when real UI is available.
